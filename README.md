## Описание тестируемых приложений

### Архитектура

Оба приложения реализуют идентичную бизнес-логику — сервис глоссария терминов блокчейн-технологий.

```
┌─────────────────┐     ┌─────────────────┐
│   Locust        │     │   Locust        │
│   REST Client   │     │   gRPC Client   │
└────────┬────────┘     └────────┬────────┘
         │ HTTP/JSON             │ HTTP/2 + Protobuf
         ▼                       ▼
┌─────────────────┐     ┌─────────────────┐
│   FastAPI       │     │   gRPC Server   │
│   REST API      │     │   (Python)      │
│   Port: 8000    │     │   Port: 50051   │
└────────┬────────┘     └────────┬────────┘
         │                       │
         ▼                       ▼
┌─────────────────────────────────────────┐
│              SQLite Database            │
│              (glossary.db)              │
└─────────────────────────────────────────┘
```

### REST API (FastAPI)

**Технологии:**
- FastAPI 0.115.6
- Uvicorn 0.34.0 (ASGI сервер)
- SQLAlchemy 2.0.36 (ORM)
- Pydantic 2.8.2 (валидация)
- SQLite (база данных)

**Эндпоинты:**

| Метод | Endpoint | Описание | Трудоёмкость |
|-------|----------|----------|--------------|
| GET | `/terms` | Получить все термины | Средняя (выборка из БД) |
| GET | `/terms/{keyword}` | Получить термин по ключу | Низкая (поиск по индексу) |
| GET | `/terms?category=X` | Фильтр по категории | Средняя |
| GET | `/categories` | Список категорий | Низкая |
| POST | `/terms` | Создать термин | Высокая (INSERT + валидация) |
| PUT | `/terms/{keyword}` | Обновить термин | Средняя (UPDATE) |
| DELETE | `/terms/{keyword}` | Удалить термин | Средняя (DELETE) |
| GET | `/health` | Проверка здоровья | Минимальная |

### gRPC Service

**Технологии:**
- grpcio 1.60.0
- grpcio-tools 1.60.0
- protobuf 4.25.1
- SQLAlchemy 2.0.25 (ORM)
- SQLite (база данных)

**RPC методы:**

| Метод | Описание | Аналог REST |
|-------|----------|-------------|
| GetAllTerms | Получить все термины | GET /terms |
| GetTerm | Получить термин по ключу | GET /terms/{keyword} |
| CreateTerm | Создать термин | POST /terms |
| UpdateTerm | Обновить термин | PUT /terms/{keyword} |
| DeleteTerm | Удалить термин | DELETE /terms/{keyword} |
| GetCategories | Список категорий | GET /categories |
| HealthCheck | Проверка здоровья | GET /health |

### База данных

**Схема таблицы `terms`:**

| Поле | Тип | Описание |
|------|-----|----------|
| id | INTEGER | Первичный ключ (AUTO INCREMENT) |
| keyword | VARCHAR(200) | Ключевое слово (UNIQUE, INDEX) |
| definition | TEXT | Определение термина |
| category | VARCHAR(100) | Категория (INDEX) |
| created_at | DATETIME | Дата создания |
| updated_at | DATETIME | Дата обновления |

**Начальные данные:** 12 терминов блокчейн-тематики.

## Установка

### 1. Установка зависимостей

```bash
cd locust
pip install -r requirements.txt
```

### 2. Компиляция Proto файлов (для gRPC тестов)

```bash
python compile_proto.py
```

Это создаст файлы:
- `glossary_pb2.py` - классы сообщений
- `glossary_pb2_grpc.py` - клиентские стабы

### 3. Запуск тестируемых сервисов

**REST API:**
```bash
cd ../REST
pip install -r requirements.txt
python -m app.main
# Сервер запустится на http://localhost:8000
```

**gRPC Service:**
```bash
cd ../gRPC
pip install -r requirements.txt
python -m grpc_tools.protoc -I./proto --python_out=. --grpc_python_out=. ./proto/glossary.proto
python -m app.server
# Сервер запустится на localhost:50051
```

## Тестовые сценарии

### 1. Sanity Check (Лёгкая нагрузка)

**Цель:** Проверка базовой работоспособности

| Параметр | Значение |
|----------|----------|
| Пользователей | 5 |
| Spawn Rate | 1/s |
| Длительность | 1 минута |
| Ожидаемый RPS | 5-10 |
| Max Latency | 500ms |

**Гипотеза:** Система должна работать стабильно без ошибок.

### 2. Normal (Рабочая нагрузка)

**Цель:** Имитация реалистичного использования

| Параметр | Значение |
|----------|----------|
| Пользователей | 20 |
| Spawn Rate | 2/s |
| Длительность | 3 минуты |
| Ожидаемый RPS | 20-50 |
| Max Latency | 1000ms |

**Гипотеза:** Типичная нагрузка для небольшого внутреннего сервиса.

### 3. Stress (Стресс-тест)

**Цель:** Выявление пределов производительности

| Параметр | Значение |
|----------|----------|
| Пользователей | 100 |
| Spawn Rate | 10/s |
| Длительность | 5 минут |
| Ожидаемый RPS | 50-200 |
| Max Latency | 3000ms |

**Гипотеза:** Определение точки деградации производительности.

### 4. Stability (Тест на стабильность)

**Цель:** Проверка деградации при длительной нагрузке

| Параметр | Значение |
|----------|----------|
| Пользователей | 30 |
| Spawn Rate | 3/s |
| Длительность | 10 минут |
| Ожидаемый RPS | 30-60 |
| Max Latency | 1500ms |

**Гипотеза:** Система не должна деградировать со временем.

### 5. Peak (Пиковая нагрузка)

**Цель:** Определение максимальной пропускной способности

| Параметр | Значение |
|----------|----------|
| Пользователей | 200 |
| Spawn Rate | 20/s |
| Длительность | 3 минуты |
| Ожидаемый RPS | 100-500 |
| Max Latency | 5000ms |

**Гипотеза:** Определение потолка производительности.

### Логика поведения пользователя

```
┌─────────────────────────────────────────────────────────┐
│                Task Flow (веса задач)                    │
├─────────────────────────────────────────────────────────┤
│  GET /terms (все термины)        ████████████████ 10    │
│  GET /terms/{keyword}            █████████████ 8        │
│  GET /terms?pagination           ███████ 5              │
│  GET /terms?category             ██████ 4               │
│  GET /categories                 ████ 3                 │
│  GET /health                     ███ 2                  │
│  POST /terms (создание)          ███ 2                  │
│  PUT /terms/{keyword}            ██ 1                   │
│  DELETE /terms/{keyword}         ██ 1                   │
└─────────────────────────────────────────────────────────┘
```

Соотношение операций: **~90% чтение / ~10% запись**

## Запуск тестов

### Через веб-интерфейс Locust

**REST API:**
```bash
locust -f locustfile_rest.py --host=http://localhost:8000
# Откройте http://localhost:8089
```

**gRPC:**
```bash
locust -f locustfile_grpc.py --host=localhost:50051
# Откройте http://localhost:8089
```

### Headless режим (без UI)

**Одиночный тест:**
```bash
python run_tests.py --scenario sanity --target rest
python run_tests.py --scenario stress --target grpc
```

**Все сценарии:**
```bash
python run_tests.py --scenario all --target both
```

### Параметры запуска

```bash
python run_tests.py --help

Options:
  --scenario, -s    Сценарий: sanity, normal, stress, stability, peak, all
  --target, -t      Цель: rest, grpc, both
  --web, -w         Запуск с веб-интерфейсом
  --users, -u       Переопределить кол-во пользователей
  --spawn-rate, -r  Переопределить spawn rate
  --run-time        Переопределить время (например, '5m')
```

### Примеры

```bash
# Быстрая проверка REST
python run_tests.py -s sanity -t rest

# Стресс-тест gRPC с 150 пользователями
python run_tests.py -s stress -t grpc -u 150

# Полное сравнение REST и gRPC
python run_tests.py -s all -t both

# Запуск с веб-интерфейсом
python run_tests.py -s normal -t rest --web
```

## Интерпретация результатов

### Признаки деградации

1. **Резкий рост латентности** при увеличении пользователей
2. **Падение RPS** несмотря на рост нагрузки
3. **Увеличение ошибок** (5xx, timeout)
4. **Нестабильность метрик** (большой разброс p95/p99)

### Типичные бутылочные горлышки

| Симптом | Вероятная причина |
|---------|------------------|
| CPU 100% | Недостаточно вычислительных ресурсов |
| Высокая латентность БД | SQLite блокировки / медленные запросы |
| Connection refused | Исчерпан лимит соединений |
| Timeout | Очередь запросов переполнена |

### Ожидаемые различия REST vs gRPC

| Аспект | REST (JSON) | gRPC (Protobuf) |
|--------|-------------|-----------------|
| Размер сообщения | Больше | Меньше (~30-50%) |
| Сериализация | Медленнее | Быстрее |
| Установка соединения | Каждый запрос* | Переиспользуется |
| Латентность | Выше | Ниже |
| Пропускная способность | Ниже | Выше |

*При использовании HTTP/1.1 без keep-alive

## Troubleshooting

### Ошибка "Proto файлы не найдены"

```bash
python compile_proto.py
```

### Ошибка подключения к серверу

1. Убедитесь, что сервер запущен
2. Проверьте порт: REST (8000), gRPC (50051)
3. Проверьте файрволл

### Низкая производительность тестов

1. Закройте другие приложения
2. Используйте headless режим
3. Уменьшите количество пользователей

### gRPC ошибки соединения

```bash
# Проверка доступности gRPC сервера
python -c "import grpc; ch = grpc.insecure_channel('localhost:50051'); print('OK')"
```
